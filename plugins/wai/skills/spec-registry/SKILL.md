# /spec-registry

Pairs with any `<domain>-standards-compliance-checker` agent generated by the `create-standards-checker` skill. Manages `.claude/compliance-specs.json` (the alias → spec-path registry) for the current repo. One registry per repo, shared across every generated agent.

## Subcommands

Parse `$ARGUMENTS`. First token = action.

| Action | Effect |
|---|---|
| (none) or `list` | Print current registry. One row per alias: alias, path, edition (if set), exists? (✓/✗), file size if PDF. |
| `check` | Validate every entry. Report broken paths, unreadable files, stale editions (e.g. registry says "Edition 2" but PDF title page says Edition 1), and dir-vs-file mismatches. |
| `add <alias> <path> [edition] [notes]` | Append a new alias. Refuse if alias already exists (suggest `update`). Verify file/dir exists before writing. |
| `update <alias> <field>=<value> ...` | Patch an existing entry. Fields: `path`, `edition`, `type`, `notes`. Verify path if changed. |
| `remove <alias>` | Delete an entry. Confirm with user first. |
| `init` | Create the registry file with a starter skeleton (empty `specs`, sensible `default_code_globs`). Refuse if file already exists. |
| `where` | Print which of the three search locations the registry resolves from, or "no registry found". |

## Registry search order (must match the agents')

1. `${repo_root}/.claude/compliance-specs.json`
2. `${repo_root}/.compliance-specs.json`
3. `${repo_root}/compliance-specs.json`

First hit wins. `init` writes to `.claude/compliance-specs.json` by default. If `.claude/` doesn't exist, create it.

## Workflow per action

### `list`

1. Resolve registry path. If none, print "no registry found, run `/spec-registry init` to create one, or run the `create-standards-checker` skill which will seed one for you."
2. Parse with `jq` or `cat | jq`.
3. For each entry: expand `~/` (use `bash -c 'echo <path>'`), then `ls` / `test -e` to confirm existence.
4. For PDFs: `pdfinfo <path>` if available, pull title + producer + page count.
5. Render as a markdown table:

   ```
   | alias | path | edition | exists | pages |
   ```

### `check`

Same as `list` plus:

- For each PDF, read page 1 (`Read` with `pages: "1-1"`) and compare the printed edition against `edition` field. Flag mismatches.
- Flag directories where the registry says a file is expected (no `type: dir`).
- Flag entries where `path` resolves outside the repo for files that the user might want repo-local.
- Exit-style summary: `N OK, M warnings, K broken`.

### `add <alias> <path> [edition] [notes]`

1. Quote-strip args. Lowercase the alias for normalization.
2. If alias already exists in registry → stop, suggest `/spec-registry update <alias> path=<path>`.
3. Expand `~/` and validate the path with `ls -la`.
4. If PDF, run `pdfinfo` and propose the detected edition as the value if `edition` wasn't supplied, confirm with user before writing.
5. Read the current registry file. If missing, run `init` first.
6. Use `jq` to splice the new entry in. Write back atomically (write to `<file>.tmp`, then `mv`).
7. Show the user the diff before writing. **Never bypass user confirmation for the write.**

### `update <alias> <field>=<value> ...`

1. Parse key=value tokens. Reject unknown fields.
2. Confirm the alias exists.
3. For `path` changes: validate the new path exists. Warn if PDF edition no longer matches `edition` field, offer to update both.
4. Show diff. Confirm. Write atomically.

### `remove <alias>`

1. Confirm alias exists.
2. **Ask the user to confirm**, show the entry being deleted.
3. `jq 'del(.specs["<alias>"])'`. Write atomically.

### `init`

1. If any of the three registry paths already exist → stop, print which one and exit.
2. `mkdir -p .claude/`.
3. Write this skeleton:

   ```json
   {
     "specs": {},
     "default_code_globs": ["src/**", "pkg/**", "lib/**"]
   }
   ```

4. Tell the user to populate via `/spec-registry add` or by re-running the `create-standards-checker` skill.

### `where`

Walk the three search locations in order. Report the first hit, or "no registry found". Print absolute path.

## Hard rules

- Use `jq` for all JSON read/write. Never hand-edit JSON via `sed` or `awk`.
- Write atomically (`<file>.tmp` → `mv`). Never partial-write a registry.
- Show diff and ask before any write. The user owns the file.
- Never edit code, never touch git, never run network commands.
- Do not call `WebFetch`. This command works against local state only.
- Do not invoke any compliance checker agent. This command manages the registry; the agents consume it.

## Output style

Terse tables. Use `✓` / `⚠` / `✗` for status. For `check` results, group by status, broken first, warnings second, OK last.
